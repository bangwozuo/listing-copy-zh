# 使用示例

以下示例的输入均为**真实可跑数据**，结果由 `scripts/run_flow.py` 端到端实跑产生。

---

## 示例 1：3 条卖点全部通过双闸（本工作流主场景）

**输入**（`examples/input.json`）：Amazon 保温杯，3 条卖点 + 检测证据。

**输出**（实跑）：

| # | 步骤 | 状态 | 关键结果 |
|---|---|---|---|
| 1 | 输入校验 | ✅ | payload 完整；平台 Amazon |
| 2 | selling-point-copy | ✅ | 可用 3 / 3；待整改 0 |
| 3 | adlaw-compliance-precheck | ✅ | 红线 0 / 警告 0；回环 0 次 |
| 4 | 汇总交付 | ✅ | 交付 3 条卖点；结论「通过」 |

---

## 示例 2：卖点含违禁词（第 2 步就拦下）

**输入**：

```json
{
  "platform": "Amazon",
  "product_info": {"品名": "304 不锈钢真空保温杯 500ml"},
  "points": ["全网最低价，100%保温，永久不漏", "采用优质材料"]
}
```

**输出**（实跑）：

| # | 步骤 | 状态 | 关键结果 |
|---|---|---|---|
| 2 | selling-point-copy | ⚠️ 无可用卖点 | 可用 0 / 2；待整改 2 |
| 3 | adlaw-compliance-precheck | ⏭ 跳过 | 第 2 步无可用卖点，闸门无输入 |

**双闸的分工**：

| 闸 | 拦什么 | 本示例命中 |
|---|---|---|
| 第 2 步（质量闸） | 长度、FAB 三要素、首条差异化、证据、违禁词 | 「优质」无信息量形容词；「最低/100%/永久」绝对化 |
| 第 3 步（法规闸） | 四类《广告法》规则 | 无输入（已被上一闸拦下） |

**整改前后对照**：

| ❌ 整改前 | ✅ 整改后 |
|---|---|
| 全网最低价，100%保温，永久不漏 | 12 小时保温（实测样本 3 次），杯盖密封倒置不漏 |
| 采用优质材料 | 食品级 304 不锈钢内胆，浸出量符合 GB 4806.9（报告号 SZ2026-1188） |

## 示例 3：FAB 不全（标注补充，不中止）

**输入**：

```json
{
  "platform": "淘宝",
  "product_info": {"品名": "304 不锈钢真空保温杯"},
  "points": ["容量 500ml", "内胆 304 不锈钢"]
}
```

**输出**（实跑）：第 2 步判「可用 0 / 2」——两条都只有 Feature、缺 Advantage 与 Benefit。
交付物里列入「待整改」，并给出 FAB 补全方向：

| 原句 | 补全后（F→A→B） |
|---|---|
| 容量 500ml | 500ml 容量够装一大杯，办公室一上午不用续水 |
| 内胆 304 不锈钢 | 304 不锈钢内胆耐腐蚀，泡茶不串味，冲洗即净 |

---

## 示例 4：输入不完整（中止，不硬跑）

**输入**：

```json
{
  "platform": "Amazon"
}
```

**输出**（实跑）：第 1 步 ❌ 中止，关键结果「缺字段: product_info」，
`flow_result.json` 中 `aborted: true`。工作流**不会**在缺少商品参数时编造卖点。
