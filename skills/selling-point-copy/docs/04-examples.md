## 示例 1：Amazon 五点描述 · FAB 完整度校验（本技能主场景）

**输入**（节选自 `examples/input.json`）：

```json
{
  "platform": "Amazon",
  "product_info": {"品名": "304 不锈钢真空保温杯 500ml", "材质": "304 内胆 + 316 外壳"},
  "evidence": ["GB 4806.9 检测报告号 SZ2026-1188", "自测：500ml 热水 12h 后 ≥ 55℃（样本 3 次）"],
  "points": [
    "304不锈钢内胆耐腐蚀，泡茶泡咖啡不串味，杯身冲洗即净",
    "采用优质材料",
    "全网最低价，100%保温，永久不漏，比某品牌好，加微信领券"
  ]
}
```

**输出**（实跑）：5 条中 3 条可用；「采用优质材料」命中「无信息量形容词」；
最后一条命中 7 处违规（绝对化 3 + 促销导流 3 + 贬低竞品 1）。

**整改前后对照**：

| | 卖点 | 结论 |
|---|---|---|
| ❌ 整改前 | 采用优质材料 | FAB 仅 F，且含空话 |
| ✅ 整改后 | 食品级 304 不锈钢内胆，浸出量符合 GB 4806.9（报告号 SZ2026-1188），入口更放心 | F→A→B 齐全，带证据 |

## 示例 2：抖音商品卡卖点（40 字红线）

**输入**：

```json
{
  "platform": "抖音",
  "points": [
    "保温杯 304不锈钢内胆 12小时保温 杯盖密封倒置不漏",
    "304不锈钢真空保温杯大容量办公室便携带茶隔学生水杯送礼首选款"
  ]
}
```

**输出**（实跑）：抖音单条建议 ≤ 40 字。第 1 条 24 字 → ✅；第 2 条 31 字 → ✅。
把 `platform` 换成 `拼多多`（≤ 30 字），第 2 条立即变 🔴 超限——
同一句卖点跨平台不可直接复用，必须按平台字数重排。

## 示例 3：FAB 只到第 1 层（不合格）

**输入**：

```json
{
  "platform": "淘宝",
  "points": ["容量 500ml", "内胆 304 不锈钢", "杯身重量 320g"]
}
```

**输出**（实跑）：三条全部判「补充收益（FAB 不全）」——只有 Feature，没有 Advantage 与 Benefit。
脚本给出的整改方向：

| 原句 | 整改后（F→A→B） |
|---|---|
| 容量 500ml | 500ml 容量够装一大杯，办公室一上午不用续水 |
| 内胆 304 不锈钢 | 304 不锈钢内胆耐腐蚀，泡茶不串味，冲洗即净 |
| 杯身重量 320g | 空杯 320g，比同容量玻璃杯轻，通勤背着不压肩 |

## 示例 4：无证据不得写强表述（证据分级）

**输入**：

```json
{
  "platform": "Amazon",
  "evidence": [],
  "points": ["永久保温，绝对不漏"]
}
```

**输出**（实跑）：命中「绝对化·功效断言」2 处（永久 / 绝对），🔴 需修改。
无 `evidence` 时须按保守表述改写：

> 保温 12 小时（实验室口径，实际受环境影响），杯盖密封设计倒置不漏。
