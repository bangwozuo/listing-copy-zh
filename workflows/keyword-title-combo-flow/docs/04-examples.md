# 使用示例

以下示例的输入均为**真实可跑数据**，结果由 `scripts/run_flow.py` 端到端实跑产生。

---

## 示例 1：3 个候选全部通过闸门（本工作流主场景）

**输入**（`examples/input.json`）：淘宝保温杯，3 个标题候选 + 关键词层级表。

**输出**（实跑）：

| # | 步骤 | 状态 | 关键结果 |
|---|---|---|---|
| 1 | 输入校验 | ✅ | payload 完整；平台 淘宝 |
| 2 | keyword-combination | ✅ | 可用 3 个；推荐「保温杯 304不锈钢 500ml 办公室便携带茶隔」（25/60） |
| 3 | adlaw-compliance-precheck | ✅ | 红线 0 / 警告 0；回环 0 次 |
| 4 | 汇总交付 | ✅ | 交付 3 个标题；结论「通过」 |

**要点**：闸门**一次通过**，回环 0 次——这是「标题先合规、再交付」的正常路径。

## 示例 2：候选含违禁词（闸门拦截 + 回环）

**输入**：

```json
{
  "platform": "淘宝",
  "core_word": "保温杯",
  "product_info": {"品名": "304 不锈钢真空保温杯", "规格": "500ml"},
  "candidate_titles": [
    "全网最低价保温杯 100%保温 销量第一",
    "保温杯 304不锈钢 500ml 办公室便携带茶隔"
  ]
}
```

**输出**（实跑）：
- 第 2 步：候选 1 被 `keyword-combination` 的五项校验判「需修改」（违禁词），
  仅候选 2 进入闸门
- 第 3 步：红线 0 → 通过

**整改前后对照**：

| | 标题 | 结论 |
|---|---|---|
| ❌ 整改前 | 全网最低价保温杯 100%保温 销量第一 | 🔴 违禁（最低 / 100% / 第一） |
| ✅ 整改后 | 保温杯 304不锈钢 500ml 办公室便携带茶隔 | ✅ 五项全过 |

## 示例 3：输入不完整（中止，不硬跑）

**输入**：

```json
{
  "platform": "淘宝"
}
```

**输出**（实跑）：

| # | 步骤 | 状态 | 关键结果 |
|---|---|---|---|
| 1 | 输入校验 | ❌ 中止 | 缺字段: product_info |

交付结论：**输入不完整，流程中止**（`flow_result.json` 中 `aborted: true`），
并给出缺失字段清单。工作流**不会**在没有商品信息的情况下硬编造标题。

---

## 示例 4：全部候选不合格（跳过闸门）

**输入**：

```json
{
  "platform": "抖音",
  "core_word": "保温杯",
  "product_info": {"品名": "304 不锈钢真空保温杯"},
  "candidate_titles": ["304不锈钢真空保温杯500ml大容量办公室便携带茶隔学生水杯（超30字）"]
}
```

**输出**（实跑）：抖音上限 30 字，该候选 27 字若合规则通过；若改写为超长版本，
第 2 步判「无可用候选」，第 3 步记为 `⏭ 跳过`（闸门无输入），
交付「无可用标题，需修改素材后重跑」——**不会**把不合格候选硬塞给闸门。
